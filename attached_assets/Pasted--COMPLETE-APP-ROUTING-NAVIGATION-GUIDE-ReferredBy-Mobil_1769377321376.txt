    |                               +--> Enter Mobile
    |                               |
    |                               +--> Send OTP
    |                               |
    |                               v
    |                           [/auth/verify-otp] (type=password_reset)
    |                               |
    |                               +--> Enter OTP
    |                               |
    |                               +--> Enter New Password
    |                               |
    |                               v
    |                           [Password Reset Success] --> [/auth/login]

    +--> Enter Password
    |

    |        |

### B. Signup Flow (NEW USER)

```text
[/auth/signup]
    |
    +--> Enter Mobile Number
    |
    +--> Select Referring Party Type:
    |    - Employee
    |    - Community Group
    |    - Business Partner
    |
    +--> Enter Referring Party ID
    |
    +--> [Send OTP]
    |
    v
[/auth/verify-otp] (type=registration)
    |
    +--> Enter OTP Code
    |
    +--> API Call: POST /api/auth/verify-otp
    |        |
    |        +--> Creates User Account (membership_status: "AA")
    |        +--> Returns user_id
    |        +--> Stores user_id in sessionStorage
    |
    v
[/auth/personal-info]
    |
    +--> Enter: First Name, Last Name, Email, ID Number, Date of Birth
    |
    +--> Set Password
    |
    +--> API Call: POST /api/auth/signup
    |        |
    |        +--> Updates user record
    |
    v
[/auth/employer-info]
    |
    +--> Enter: Employer Name, Employee Number, Monthly Salary, Work Email
    |
    +--> API Call: PATCH /api/users/[user_id]
    |
    v
[/auth/community]
    |
    +--> Select Community Group (Dropdown)
    |
    +--> API Call: PATCH /api/users/[user_id]
    |
    v
[/auth/upload-selfie]
    |
    +--> Capture/Upload Selfie Photo
    |
    +--> API Call: POST /api/upload/selfie
    |        |
    |        +--> Uploads to Vercel Blob
    |        +--> Saves URL to users.selfie_photo_url
    |
    v
[/auth/upload-documents]
    |
    +--> Upload National ID (PDF/Image)
    |
    +--> Upload Proof of Income/Payslip (PDF/Image)
    |
    +--> API Call: POST /api/upload/documents
    |        |
    |        +--> Uploads both files to Vercel Blob
    |        +--> Creates records in user_documents table
    |
    v
[/auth/signup-success]
    |
    +--> "Registration Complete! Awaiting Approval"
    |
    +--> [Continue to Login] --> [/auth/login]
```

**CRITICAL NOTES:**
- User is created with `membership_status: "AA"` after OTP verification
- No session is created during onboarding
- User must log in after completing registration
- All onboarding routes use `user_id` from sessionStorage (no auth required)

## 3. USER ONBOARDING FLOW

### Onboarding Route Sequence

```text
[After OTP Verification - User Created]
    |
    v
[/auth/personal-info] (Step 1 of 5)
    |
    +--> Status: AA (Awaiting Approval)
    +--> sessionStorage.user_id: {uuid}
    |
    v
[/auth/employer-info] (Step 2 of 5)
    |
    +--> Updates employer details
    |
    v
[/auth/community] (Step 3 of 5)
    |
    +--> Assigns lending society
    |
    v
[/auth/upload-selfie] (Step 4 of 5)
    |
    +--> KYC: Selfie verification
    +--> NO AUTH REQUIRED (uses user_id)
    |
    v
[/auth/upload-documents] (Step 5 of 5)
    |
    +--> KYC: National ID + Payslip
    +--> NO AUTH REQUIRED (uses user_id)
    |
    v
[/auth/signup-success]
    |
    +--> Onboarding Complete
    +--> User must now LOGIN
    +--> Admin will approve (AA → AP1 → AP2)
```

**KEY ONBOARDING RULES:**
1. All routes from `/auth/personal-info` to `/auth/signup-success` do NOT require authentication
2. They use `user_id` stored in sessionStorage
3. User account exists but session does not
4. User MUST login after signup-success

## 5. LOAN APPLICATION FLOWS

### A. Nano Loan Application Flow

```text
[/loans/apply?type=nano]
    |
    +--> API Call: GET /api/mobile/loan-request?loan_type=nano
    |        |
    |        +--> Checks: membership_status = AP2
    |        +--> Checks: lending_societies.nano_loans_enabled = TRUE
    |        +--> Fetches: nano_progression limits (current_max_nano)
    |        +--> Returns: loan limits and eligibility
    |
    +--> (if NOT eligible) --> [Error Message: "Nano loans not available"]
    |                              |
    |                              +--> [Back to Dashboard]
    |
    v
[Display Nano Loan Request Form]
    |
    +--> Shows: Min/Max loan amounts
    +--> Account Level: NL1-NL9
    +--> Max Amount: Based on progression.current_max_nano
    |
    +--> User enters loan amount
    |
    +--> [Read Terms & Conditions] (checkbox)
    |
    +--> [Read Digital Contract] (checkbox)
    |
    +--> [CONTINUE] (disabled until both checked)
    |
    v
[/loans/interest-confirmation]
    |
    +--> Shows: Loan amount, interest rate, repayment date
    |
    +--> User confirms interest acknowledgment
    |
    +--> [SUBMIT LOAN REQUEST]
    |
    +--> API Call: POST /api/mobile/interest-confirmation
    |        |
    |        +--> Creates nano_loans record (status: PA - Pending Approval)
    |        +--> Sends notification to admin
    |
    v
[Success Message]
    |
    +--> "Loan request submitted. Awaiting approval."
    |
    +--> [View Statements] --> [/loans/active-statement]
    |
    +--> [Back to Dashboard] --> [/]
```

**Nano Loan States:**
- **PA**: Pending Approval (awaiting admin)
- **AP**: Approved (ready for disbursement)
- **DI**: Disbursed (active loan)
- **PU**: Paid Up (settled)
- **DE**: Defaulted

### B. Term Loan Application Flow

```text
[/loans/term-loan]
    |
    +--> API Call: GET /api/mobile/loan-request?loan_type=term
    |        |
    |        +--> Checks: membership_status = AP2
    |        +--> Checks: lending_societies.term_loans_enabled = TRUE
    |        +--> Fetches: term_progression limits (current_max_term)
    |        +--> Returns: loan limits and eligibility
    |
    +--> (if NOT eligible) --> [Error Message: "Term loans not available"]
    |                              |
    |                              +--> [Back to Dashboard]
    |
    v
[Display Term Loan Request Form]
    |
    +--> Shows: Min/Max loan amounts
    +--> Account Level: TL0-TL10
    +--> Max Amount: Based on progression.current_max_term
    |
    +--> User selects: Loan amount, repayment period (months)
    |
    +--> [Read Terms & Conditions] (checkbox)
    |
    +--> [CONTINUE]
    |
    v
[/loans/term-loan/net-disposable-income]
    |
    +--> User enters: Monthly income, deductions, expenses
    |
    +--> Calculates: Net Disposable Income (NDI)
    |
    +--> Validates: Monthly installment ≤ 50% of NDI
    |
    +--> [CONTINUE]
    |
    v
[/loans/term-loan/bank-details]
    |
    +--> User enters: Bank name, account number, account holder name
    |
    +--> [CONTINUE]
    |
    v
[/loans/term-loan/bank-authorization]
    |
    +--> User uploads: Bank authorization letter (PDF)
    |
    +--> API Call: POST /api/term-loan/upload-documents
    |        |
    |        +--> Uploads to Vercel Blob
    |        +--> Saves to user_documents
    |
    +--> [SUBMIT TERM LOAN REQUEST]
    |
    +--> API Call: POST /api/term-loan/submit
    |        |
    |        +--> Creates term_loans record (status: PA)
    |        +--> Creates term_loan_installments (all future installments)
    |        +--> Sends notification to admin
    |
    v
[Success Message]
    |
    +--> "Term loan request submitted. Awaiting approval."
    |
    +--> [View Statements] --> [/loans/active-statement]
    |
    +--> [Back to Dashboard] --> [/]
```

**Term Loan States:**
- **PA**: Pending Approval
- **AP**: Approved
- **DI**: Disbursed (active)
- **AC**: Active (same as DI)
- **SE**: Settled (fully paid)
- **DE**: Defaulted

### Credit Score History Flow

```text
[/profile/credit-score-history]
    |
    +--> API Call: GET /api/users/me
    |        |
    |        +--> Returns: borrower_rating, rating events
    |
    +--> API Call: GET /api/users/[user_id]/rating-events
    |        |
    |        +--> Returns: all rating_events ordered by date
    |
    +--> Displays:
    |    - Current Rating: X.X / 10 (star display)
    |    - Rating Label: EXCELLENT / GOOD / FAIR / POOR
    |    - Total Score: XX / 100
    |
    +---[SCORE BREAKDOWN]---+
    |   |
    |   +--> Early Payments: +XX pts (green)
    |   +--> On-Time Payments: +XX pts (blue)
    |   +--> Late Penalties: -XX pts (red)
    |   +--> Referral Bonus: +XX pts (purple)
    |
    +---[RATING HISTORY]---+
        |
        +--> [Event 1] settled_early | +5 pts | Date | Loan ID
        +--> [Event 2] settled | +10 pts | Date | Loan ID
        +--> [Event 3] late_payment | -5 pts | Date | Loan ID
        ...
```

**Rating System (V1 Spec):**
- **Before Due Settlement**: +5 points
- **On-Time Payment**: +10 points
- **Grace Period (1-3 days)**: 0 points
- **Minor Late (4-7 days)**: -5 points
- **Major Late (8+ days)**: -10 points
- **3 Consecutive On-Time Cycles**: +5 bonus

**Rating Scale:**
- 0.0 - 4.9: POOR
- 5.0 - 6.9: FAIR
- 7.0 - 8.9: GOOD
- 9.0 - 10.0: EXCELLENT

## 8. CONDITIONAL ROUTING LOGIC

### Authentication Guards

```text
PUBLIC ROUTES (No Auth Required):
    - /auth/login
    - /auth/signup
    - /auth/forgot-password
    - /auth/verify-otp

ONBOARDING ROUTES (User Exists, No Session):
    - /auth/personal-info
    - /auth/employer-info
    - /auth/community
    - /auth/upload-selfie
    - /auth/upload-documents
    - /auth/signup-success

PROTECTED ROUTES (Auth Required):
    - / (Dashboard)
    - /profile/*
    - /loans/*

AUTH CHECK:
    - Checks for session token in cookies
    - If missing → Redirect to /auth/login
    - If present → Allow access
```

### Membership Status Checks

```text
LOAN REQUEST ELIGIBILITY:

[Request Nano Loan Button]
    |
    +--> Check: membership_status
    |        |
    |        +--> If "AA" or "AP1" → BLOCKED
    |        |        |
    |        |        +--> Show: "Complete your registration and wait for approval"
    |        |
    |        +--> If "AP2" → Check nano_loans_enabled
    |                 |
    |                 +--> If FALSE → BLOCKED
    |                 |        |
    |                 |        +--> Show: "Nano loans not available for your lending society"
    |                 |
    |                 +--> If TRUE → ALLOW
    |                          |
    |                          v
    |                      [/loans/apply?type=nano]

[Apply for Term Loan Button]
    |
    +--> Check: membership_status
    |        |
    |        +--> If "AA" or "AP1" → BLOCKED
    |        |        |
    |        |        +--> Show: "Complete your registration and wait for approval"
    |        |
    |        +--> If "AP2" → Check term_loans_enabled
    |                 |
    |                 +--> If FALSE → BLOCKED
    |                 |        |
    |                 |        +--> Show: "Term loans not available for your lending society"
    |                 |
    |                 +--> If TRUE → ALLOW
    |                          |
    |                          v
    |                      [/loans/term-loan]
```

**Membership Status Definitions:**
- **AA**: Awaiting Approval (newly registered, docs pending)
- **AP1**: Approved Level 1 (KYC complete, can view profile only)
- **AP2**: Approved Level 2 (fully approved, can apply for loans)

### Lending Society Configuration

```text
LOAN TYPE AVAILABILITY:

Database: lending_societies table
    |
    +--> nano_loans_enabled: BOOLEAN
    |    - TRUE: Society allows nano loans
    |    - FALSE: Society does not offer nano loans
    |
    +--> term_loans_enabled: BOOLEAN
         - TRUE: Society allows term loans
         - FALSE: Society does not offer term loans

API Check:
    GET /api/mobile/loan-request?loan_type=nano
        |
        +--> Queries: lending_societies WHERE id = user.lending_society_id
        +--> Returns: nano_loans_enabled status
        +--> If FALSE → 403 Error: "Nano loans not available"
```

        |        |        +--> Show: "Maximum allowed: NAD 2000"
        |        |

## 11. ERROR HANDLING & REDIRECTS

### Authentication Errors

```text
[User accesses protected route without auth]
    |
    +--> Redirect to: /auth/login
    +--> Store intended destination
    +--> After login → Redirect to intended destination

[Session expired]
    |
    +--> Clear session
    +--> Redirect to: /auth/login
    +--> Show: "Session expired. Please log in again."

[Invalid credentials]
    |
    +--> Stay on: /auth/login
    +--> Show: "Invalid mobile number or password"
```

---

### Loan Request Errors

```text
[User not eligible for loan type]
    |
    +--> Show error message on current page
    +--> Button remains disabled
    +--> No navigation

[Loan amount exceeds limit]
    |
    +--> Show validation error inline
    +--> Prevent form submission
    +--> No navigation

[Lending society has disabled loan type]
    |
    +--> API returns 403
    +--> Show: "This loan type is not available for your lending society"
    +--> [Back to Dashboard] button
```

---

### Document Upload Errors

```text
[File too large (>10MB)]
    |
    +--> Show: "File size exceeds 10MB limit"
    +--> Clear file input
    +--> Stay on upload page

[Invalid file type]
    |
    +--> Show: "Please upload PDF or image files only"
    +--> Clear file input
    +--> Stay on upload page

[Upload fails (network/server error)]
    |
    +--> Show: "Upload failed. Please try again."
    +--> Retry button
    +--> Stay on upload page
```

## 12. MOBILE APP SPECIFIC CONSIDERATIONS

### Back Button Behavior

```text
ANDROID/IOS BACK BUTTON:

From Dashboard (/):
    → Exit app (or show "Press again to exit" confirmation)

From any other page:
    → Navigate to previous page in history stack

Special Cases:
    - From /auth/signup-success → Back disabled (must click "Continue to Login")
    - From /loans/interest-confirmation → Back to /loans/apply
    - From /loans/active-statement → Back to Dashboard (/)
```

---

### Deep Linking

```text
SUPPORTED DEEP LINKS:

referredby://auth/login
    → Opens login page

referredby://loans/apply?type=nano
    → Opens nano loan request (if authenticated)

referredby://profile
    → Opens user profile (if authenticated)

referredby://loans/active-statement
    → Opens active statements (if authenticated)

If user not authenticated:
    → Store deep link destination
    → Navigate to /auth/login
    → After login → Navigate to stored destination
```

---

### Offline Behavior

```text
OFFLINE MODE HANDLING:

[App opened while offline]
    |
    +--> Show: "No internet connection"
    +--> Cache last loaded profile data (read-only)
    +--> Disable all buttons requiring API calls
    +--> Show retry/refresh button

[Connection lost during form submission]
    |
    +--> Show: "Connection lost. Please try again."
    +--> Preserve form data (localStorage)
    +--> Enable retry when connection restored
```
